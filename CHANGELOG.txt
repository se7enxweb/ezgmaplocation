Version 6.1.1
-------------------------------------------------------------------------------
* Fixed: with the real Google script the map was never drawn. The loader
  reports its load a moment before google.maps.importLibrary exists; the
  script now waits for it (up to five seconds) instead of giving up, so the
  edit form and the view template draw the map. Found by the first run
  against Google's own script; 6.1.0 was only checked against a stand-in.
* Fixed: the advanced marker's drag is read from its gmp-dragend event
  (addListener on the web component logged a console warning).
* A map that cannot start now logs the reason in the console.

Version 6.1.0
-------------------------------------------------------------------------------
* Moved to the current Google Maps JavaScript API: the script adds Google's
  loader itself (loading=async) and uses importLibrary (maps, marker,
  geocoding). With [GMapSettings] MapId the markers are AdvancedMarkerElement
  and the map follows the administration's light or dark mode; without a Map
  ID the classic google.maps.Marker stays as the fallback. The address search
  uses the promise form of google.maps.Geocoder.
* New settings MapId, ApiVersion, Language and Region.
* The edit and view scripts are an expui module on the kernel's jQuery 4
  (Exp.$): no YUI, no inline script, no eval; the templates only print
  data-ezgml-* attributes. Needs the expui extension.
* Without an API key no script from Google is loaded: the latitude and
  longitude fields stay and an OpenStreetMap link shows the position. A
  refused key (gm_authFailure) or a blocked script falls back the same way.
* Added doc/ (settings, Google setup, Content Security Policy, upgrading,
  testing). The DB-less tests were rewritten for the new script.
* The old functions eZGmapLocation_MapControl() and eZGmapLocation_MapView()
  remain for override templates.

Version 6.0.12
-------------------------------------------------------------------------------
* The edit form and the view template load the Google Maps JavaScript API
  only when [GMapSettings] ApiKey is set, from https://maps.googleapis.com
  with the key URL-encoded. Without a key Google draws no map, so the pages
  no longer load a script from another host for nothing (an administration
  with an enforced Content Security Policy blocked it on every page with a
  map field). Without a key the coordinates are shown without a map and the
  map buttons stay inactive. The README lists the hosts a Content Security
  Policy has to allow when a key is set. UseSensor is not used any more.
* Added tests/ezgmaplocation_maps_api_key_test.php (DB-less).

Version 6.0.8
-------------------------------------------------------------------------------
* The address is stored as typed. The edit form passed it through
  htmlentities() before, so stored addresses hold entities such as
  "M&uuml;llerstra&szlig;e 5", and the templates now escape the address
  when they print it (|wash): without the upgrade step below these rows
  show their entities on the page.
  UPGRADE STEP, required, once, before editors work with the new version:
    php extension/ezgmaplocation/bin/php/decodeaddressentities.php -s <siteaccess>
  lists the rows it would change; check the list (rows that were never
  encoded, from a package import or fromString(), and hold a literal
  "&xxx;" are decoded as well), then run it again with --apply. Once per
  database (siteaccess). Do not run it a second time later: addresses
  saved after the upgrade are stored as typed. Search index, sort key
  and object names follow on the next publish or a reindex.
* fromString() keeps the coordinates of a string without address
  ("1|#52.5|#13.4") and stores nothing for a string without both
  coordinates, where it read undefined array keys. An address that
  contains "|#" is kept whole, and coordinates that are not numbers store
  no location (the edit form refused them already; the view template
  writes them into a script).
* The templates that put the address into a map script (cjw_themes_jumper
  0.1.4, ezflow 6.1.6) escape it for HTML and then for JavaScript
  (|wash|wash( 'javascript' )), the same order everywhere.
* ezgmaplocation.ini.append.php begins with "<?php /*": "<?php/*" is no
  PHP open tag, and a direct request to the file printed it, ApiKey
  included.

Version 0.4
-------------------------------------------------------------------------------
* Resolved a few warnings and error messages.

* Much simpler install - modified the javascript so that no template changes
  are required in the admin design.

* The editing controls will now work properly if there are multiple location
  attributes on a single object.

* In the editing view, the map will now re-center on the clicked point. This
  makes it easier to use the click-point and zoome controls to hone in on a
  specific point.

* The edit map now defaults to a zoom-level-0 view of the globe instead of
  a gray square.

* The edit map is larger, so that the map type and directional controls don't
  overlap.

* A new template has been included, gmap.tpl. This is a multi-purpose template
  that can be included and configured to handle several common use-cases for
  the gmaps datatype. See the doc on the template for specifics.
